# Мониторинг и обновление игры после выпуска

## Источники обратной связи

| Источник | Что даёт | Где смотреть |
|---|---|---|
| Анонимная аналитика | что игроки делают: где гибнут, где бросают, сколько проходят | Tools → Release → Analytics Dashboard |
| Сбор ошибок | падения и исключения с местом в коде | панель аналитики, раздел «Ошибки» |
| Отзывы из игры | оценка 1–5 и текст, тип (отзыв / ошибка / предложение) | GitHub Issues (метки feedback / bug / enhancement) |
| Отзывы в магазинах | оценки и комментарии игроков | консоль itch.io / RuStore / Google Play |
| Отчёты о сборке | размер и время сборки по версиям | Builds/build_history.csv |

## Как получить данные игроков
1. Плейтестеры: Настройки → «Анонимная статистика» включена. После игры они присылают файл `analytics/events.jsonl` из папки данных приложения
   (Windows: `%USERPROFILE%\AppData\LocalLow\Portfolio\Ball Collector\`, Android: `Android/data/com.portfolio.ballcollector/files/`).
2. Файлы кладутся в папку `AnalyticsData/` проекта (кнопка «Папка импорта» в панели) — панель читает все `*.jsonl`.
3. Для массового сбора указывается сервер в `analyticsEndpoint` удалённого конфига — игра будет отправлять события пачками POST-запросом (JSON-массив).

## Удалённый конфиг (изменения без обновления игры)
Файл `Config/remote_config.json` в репозитории. Игра скачивает его при запуске по ссылке raw.githubusercontent.com, кэширует и применяет.

| Поле | Что меняет | По умолчанию |
|---|---|---|
| barrelExplodeSpeed | скорость удара (м/с), при которой взрывается бочка | 7 |
| obstacleDamageMultiplier | множитель урона подвижных препятствий | 1.0 |
| threeStarTime / twoStarTime | нормативы времени для звёзд (с) | 90 / 150 |
| newsTitle / newsText | карточка новостей в главном меню | — |
| latestVersion / updateUrl | уведомление «Доступна версия X» | — |
| analyticsEndpoint | сервер сбора статистики (пусто — только локально) | — |
| feedbackRepo | репозиторий для отзывов | этот репозиторий |

Порядок изменения: отредактировать файл → увеличить `configVersion` → commit в main. Некорректный JSON игнорируется, значения вне безопасных диапазонов ограничиваются.

## Цикл обновления
1. **Сбор** (3–7 дней после выпуска): аналитика, ошибки, отзывы.
2. **Анализ**: панель аналитики → раздел «Рекомендации»; отзывы группируются по темам; отчёт кнопкой «Отчёт .md».
3. **Приоритизация**:
   - критические ошибки и падения → patch-версия сразу;
   - баланс → правка удалённого конфига в тот же день;
   - интерфейс и новые механики → следующая minor-версия.
4. **Изменение**: задача в GitHub Issues → исправление → автотесты → сборка.
5. **Выпуск**: повышение версии, changelog.txt (окно «Что нового»), `latestVersion` в конфиге → игроки видят уведомление.
6. **Проверка эффекта**: сравнение метрик новой и старой версии (панель показывает разбивку по версиям).

## Пример: как данные превращаются в обновление
| Наблюдение (метрика) | Порог тревоги | Действие |
|---|---|---|
| > 40 % гибелей от бочек | панель: «Бочки — причина N % гибелей» | barrelExplodeSpeed 7 → 8.5 в конфиге |
| прохождение < 30 % | «Уровень слишком сложный» | obstacleDamageMultiplier 1 → 0.8 |
| > 80 % побед на 3 звезды | «Норматив слишком лёгкий» | threeStarTime 90 → 75 |
| аптечки не используются при частых гибелях | рекомендация в панели | подсказка о клавише 1 в обновлении |
| средний FPS < 40 | раздел «Производительность» | понизить качество по умолчанию |
| повторяющаяся ошибка | раздел «Ошибки» | patch-версия с исправлением |
| средняя оценка < 3.5 | раздел «Отзывы» | разбор отзывов с низкой оценкой |
